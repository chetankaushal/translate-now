# Translate Now

React Native (Expo SDK 57 / RN 0.86.2). Every push builds and smoke-tests on
both an iOS simulator and an Android emulator. No local Xcode or Android Studio
needed, and no paid services.

## The one manual step

```bash
gh auth login
./scripts/bootstrap-repos.sh <your-github-owner>

git init && git add -A && git commit -m "Initial commit"
git branch -M main
git remote add origin git@github.com:<owner>/translate-now.git
git push -u origin main
```

`package-lock.json` is committed and was verified with a real `npm ci` plus a
clean `tsc --noEmit`, so CI does not have to resolve dependencies from scratch.

Everything after that is automatic. Artifacts land on each run's summary page:
a `.app` for the simulator, an `app-debug.apk` for the emulator, plus JUnit
results and Maestro screenshots.

No secrets are configured, because none are needed — simulator builds use
`CODE_SIGNING_ALLOWED=NO` and Android debug builds use the auto-generated debug
keystore. Your Apple and Play accounts only come into play when you want
TestFlight or Play Console delivery.

## Cost

| Piece | Cost |
|---|---|
| Expo SDK + `expo prebuild` | Free, MIT |
| Translation (ML Kit, on-device) | Free, unlimited, offline, no API key |
| Maestro CLI | Free, open source |
| GitHub Actions, public repo | Free, unlimited minutes |
| GitHub Actions, private repo | macOS bills at **10× multiplier** |

EAS Build is Expo's *paid* cloud service and is deliberately not used here.
`expo prebuild` generates `ios/` and `android/` and the workflows compile them
with plain `xcodebuild` and `gradlew`.

## Decisions worth knowing

**`ios/` and `android/` are gitignored.** They're regenerated by `expo prebuild`
on every CI run, so the native projects can never silently drift from
`app.config.ts`. All native config lives in one file.

**CI translates with a mock provider.** The real engine downloads a ~30MB model
from Google's CDN on first use. Wiring that into a smoke test means a red build
whenever the CDN is slow — the test would be measuring Google's uptime, not our
app. `src/translation/mock.ts` is deterministic and offline, so the flows still
prove the full path: TextInput → store → provider → UI. Selected via
`EXPO_PUBLIC_TRANSLATION_PROVIDER=mock`, never active in a release build.

**Adding a cloud engine** means one file implementing `TranslationProvider` and
one line in `src/translation/index.ts`. No UI changes.

## Android `minSdk` is 24, not 35

You asked for "iOS 18-equivalent year SDK" on Android. iOS 18 shipped Sept 2024;
the matching Android release is 15 = **API 35**. But `minSdk` and `targetSdk`
are not the same knob:

- `targetSdk` / `compileSdk` = which behaviours you opt into. Set high. **36 here.**
- `minSdk` = the oldest device that can install at all. **24 here (Android 7.0).**

`minSdk 35` would make the app uninstallable on roughly 90%+ of active Android
devices. If you truly want to match iOS 18's cutoff, say so and I'll change it —
but it's almost certainly not what you meant.

Note that `iOS 18.0` as a deployment target does drop iPhone X and earlier.
That's a real audience decision, not a technical one.

## Local development

```bash
npm install
npx expo prebuild
npm run ios      # or: npm run android
```

Run the smoke tests against a booted device:

```bash
MAESTRO_APP_ID=com.movil.translatenow maestro test .maestro/
```

## Layout

```
app/                    expo-router screens
src/translation/        provider interface + ML Kit + mock
src/store/              zustand state
src/components/         shared UI
.maestro/               smoke test flows
.github/workflows/      iOS simulator + Android emulator CI
```
